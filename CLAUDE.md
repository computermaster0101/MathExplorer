# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Math Explorer is a single-page static site made of plain HTML, CSS and native ES modules. It has **no build step, no package.json and no bundler**, and must stay that way: it is deployed by copying the folder to nginx. Third-party code is kept in the repo (`vendor/three/three.module.js`, three.js r128, mapped to the bare specifier `three` by the import map in `index.html`). Do not switch to a CDN or add npm dependencies.

## Running and checking

Serve the folder over HTTP (modules don't load from `file://`), for example `python -m http.server 8000`, then open `http://localhost:8000/`. After editing, reload with Ctrl+Shift+R: browsers cache the modules, and the README's nginx config sends `Cache-Control: no-cache` for the same reason. There are no tests or linters. To check a change, load the page, use the affected explorer and mode, and watch the browser console. A missing import or a load-order problem shows up as an error the moment the explorer loads.

## How the shell drives an explorer

- On first visit, `main.js` fetches `stage.html` and `panel.html`, attaches them, and then dynamically imports `index.js`. Importing that module **boots** the explorer, because its modules look up their DOM elements as they load. So the markup must be attached before the import.
- `index.js` exports the lifecycle: `start`, `stop`, `reset`, `onKey(e) → used`, `layoutChanged`, `showView(code)`. The full contract is in the header comment of `js/main.js`. To add an explorer, create a folder with those files, add it to `EXPLORERS` in `main.js`, add a menu item (`<a data-explorer=…><b>name</b><small>one line</small></a>`) to `#xList` in `index.html`, and link its `style.css`. The menu closes on a choice, a click outside or Esc.
- Only the active explorer is attached. Switching away calls `stop()` (which ends its `requestAnimationFrame` loop) and detaches its DOM, keeping the nodes. That is why explorers can use bare ids and `document.querySelector` freely. Never leave two explorers' DOM attached at once.
- Explorer CSS must be scoped as `.app[data-explorer="<name>"] …`. Every explorer's stylesheet is always loaded.
- Sleeping drawing surfaces (`sleepIn` / `wakeIn` in `js/common/gl.js`): browsers keep only a few WebGL contexts alive per page and silently kill the oldest (headless Chrome kept 2), so explorers you'd left came back black. `main.js` puts the leaving explorer's canvases to sleep after `stop()` and wakes them before `start()`, so at most Fractals' two plus the one on screen are alive. `makeGL` rebuilds its programs into the same `{ p, u }` objects and reads every `pair` back before sleeping and refills it on waking (Life, Lenia and the wave tank come back pixel for pixel), then runs `G.onWake` callbacks (each shader explorer sets `dirty`); `sleepThree(renderer)` does the three.js stages (three.js re-sends everything itself; the clear colour is put back). Waking is asynchronous, so whatever rebuilds must redraw then. A sleeping canvas has `data-asleep`, which `perf.js` ignores. Fractals doesn't sleep (reference orbits, BLA tables, slow 3D shaders); its own context-lost message stays. A new GL canvas must register (`sleeper`, `sleepThree`, or by using `makeGL` / `makeStage3D`), or it will be killed after a few switches. Checked by visiting all twelve twice with `--max-active-webgl-contexts=8` and the default.
- Explorers never touch `location.hash` or `history` directly. They use `setViewCode(name, code)` (ignored unless that explorer is active), `shareLink`, `codeFromText` (accepts pasted links or bare codes) and `parseRoute().code` at boot. Old fractal codes (`f3-…`, `f4-…`) still load through `codeFromText`.
- The buttons on the picture (`#stageBtns`, `toolbar.js`) are icons, each with its name and key on hover (`data-tip`, also the aria-label) or a long press on a touch screen (which shows the name without pressing), in four groups (`.tbGroup`): **View** (hide panel, full screen, reset view), the **Player** in the middle, laid out like a music player (back = zoom out, slower, play / pause, faster, forward = zoom in), **Go** (go, then steer itself and the explorer's own button) and **More** (♫, ⇪ share, ?). View, Go's extras and More fold away behind one icon (`.tbHandle`; `folded` in localStorage `mathexplorer.tbGroups`; phones start folded, big screens open); the ? key opens a folded More for the moment. Play / pause presses Space (the icon follows the Paused tag, and shows play while the explorer's optional `moving()` says nothing is moving: Fractals, Polytopes, Surfaces, Knots, Foams, Complex Functions, Tilings; the others always open moving); Go presses G, named by the explorer's `goLabel()` (hidden when null); the target presses T (`autoCtl()`: `{ label, on }`, lit while on; hidden elsewhere, where T keeps its own meaning); the explorer's own button is `extraCtl()` (`{ label, icon, on, run }`; Fractals' Julia swap); zoom out / in send a wheel event to whatever is under the middle of the picture (a click is a step, holding keeps going; hidden when `canZoom()` says no); slower / faster step the explorer's `speedCtl()` (a range input ×1.25, a tenth of the range when it passes through zero, `invert` when bigger is slower, or its own `step`; hidden when null). ♫ has Music settings (opens `#g-sound`) and the explorer's own `#vizStageBtn` (Start / Stop the Visualizer). ⇪ has Copy link (the address always holds this view), Share… (the system share sheet where the browser has one) and the panel's own Save picture (`#snap`), Record video (`#recBtn`; while recording the item says Stop and ⇪ has a red dot) and 3D print (`#prBtn`, Polytopes' `#export`; hidden where nothing can be printed), pressed through `press()` so their settings stay in the panel. Every press is one `toolbar` analytics event (`button`, `explorer`, sometimes `detail`; `NAMES` in `toolbar.js`, and `group_<name>` open / fold), and panel buttons pressed from the menu aren't counted again (`window.__tbClick`). The whole row is hidden in full screen, so in the Visualizer too.
- Shell-owned controls (`#panelBtn`, `#zenBtn`, `#zenExit`, `#resetBtn`, `#helpBtn`, `#tbPlay`, `#tbGo`, `#tbSteer`, `#tbExtra`, `#tbOut`, `#tbIn`, `#tbSlower`, `#tbFaster`, `#musicBtn`, `#tbShare`, `#shareMenu`, the `.tbHandle`s) and the shared keys are not bound by explorers. Each panel's keyboard group must keep the id `g-keys`, which Keyboard shortcuts in the ? menu opens.
- Keys are the same in every explorer: Space pauses and resumes everything moving (`st.paused`, gating every motion in the loop; with nothing moving it starts the mode's main motion), G dives or flies in, R resets, Z / X change shape (`,` / `.` too; Shift + Z / X change the number of dimensions on the polytopes), C / V change palette (with Shift: colour mode), B reverses the palette.
  - The driving keys (arrows and W A S D, Shift for faster) never reach `onKey`. The shell keeps them in a held set, cleared on blur, and each explorer reads `drive()` every frame. The arrows turn and W A S D slides; in 2D both pan; + / − (and the wheel) zoom everywhere.
  - `turnY` follows the shared "Invert up / down" box (`#invertY` in each `g-keys` group, saved in localStorage); `rawY` ignores it. Each axis is eased over about 0.18 s. `scale` is the shared "Navigation speed" slider (`#navSpeed`, 0.1–2, default 0.5), and explorers multiply their turn and slide speeds by it. Steering during a 3D dive is a further 0.45×, a 2D dive 0.5×, and turning in polytope flight is gentler too. Flight forward speed is separate (+ / −).
  - Space is also blocked on key-up, and auto-repeat is ignored. After a mouse click, buttons, checkboxes and sliders give up focus. Otherwise Space also pressed the last-clicked button, and holding it flipped the pause on and off.
  - Each loop calls `setPausedTag(st.paused)`.
- Touch gestures (`layout.js`, touch only): on the picture a quick, still, one-finger tap goes (presses G: dive, fly, ride, walk), or presses Space (pause / resume) when the explorer's `going()` says it is already going, when paused, or when nothing used the G (after 320 ms so a double tap can cancel it) and a double tap toggles full screen; pressing and holding still (within 10 px) for 600 ms presses R; in full screen a deliberate swipe (across 40% of the shorter side and at least 140 px, in under 300 ms, three times further one way than the other, so drags to move round never count) presses V / C (left / right: palette) or X / Z (up / down: next / previous shape). A canvas marked `data-own-taps` keeps its taps outside full screen (Growing Patterns' brush, Waves' overlay, Labyrinths in a maze, Drawing Machines while drawing your own); in full screen a tap always pauses. A tap the shell takes sets `touchTapping()` for 400 ms, which explorers' own tap actions check (Fractals' fly-to-a-spot, orbit point and dive steering, the maze's step); Fractals' double-click zoom checks `recentTouch()`. While a touch screen is in use (`.app.touch`), full screen shows nothing but the picture, with a tip for a moment on the way in.
- First visits (`js/shell/tour.js`): an eight-step tour of what every explorer shares (the menu, moving round the picture, the buttons on the picture, the panel, music, save and share, 3D print, keys and help; each panel-group step opens its group while shown and closes it after, and a group hidden in the current mode is skipped) and, the first time in each explorer, a card (`CARDS`: what you're looking at, and two things to try that only that explorer has; never colours, music or sharing, which the tour covers). Remembered in localStorage (`mathexplorer.tour` = version, `mathexplorer.card.<explorer>`), else sessionStorage. The tour starts straight away on a first visit; the consent bar sits above it (z-index) and the tour keeps its card above the bar (`room()`). A shared link (a view code in the address) gets a small bar offering the tour instead; nothing shows in full screen; the **?** button at the end of the buttons on the picture (`#helpBtn`, `toggleHelp()` in `layout.js`; the ? and / keys open it too) has Take the tour, About this explorer, Keyboard shortcuts, Report a problem, Privacy and Source code on GitHub (also the small GitHub mark in the panel header, `#ghLink`); like the other picture buttons it never shows in full screen, so not in the Visualizer either, and the keys do nothing there. Skipping the tour, or closing the shared-link bar, shows a hint under the ? for a few seconds (`laterHint`). Automated browsers (`navigator.webdriver`) skip it unless the address has `?tourTest` or `?analyticsTest`, so the test scripts aren't blocked.
- Report a problem (`js/shell/report.js`, in the ? menu): a form posted to the Lambda in `aws/report/index.mjs` (function URL, CORS for the live site only, reserved concurrency 2), which reads a fine-grained GitHub token (Issues on MathExplorer only) from the SSM SecureString `/mathexplorer/github-token` and opens an issue labelled `from-site`. Issues are public, so it asks for nothing personal; it sends what happened, optionally the view link, the explorer, browser, screen size and the page's last few error messages. Guards in the Lambda: origin check, size limits, a hidden trap field, 3 per visitor per 10 minutes and 30 an hour, @mentions defused. To update it: zip `index.mjs` and `aws lambda update-function-code --function-name mathexplorer-report`. Its role `mathexplorer-report-lambda` can read that one parameter and write its own logs, nothing else.
- Search and sharing: `index.html` carries a descriptive title (kept on the bare home page; `main.js` names the explorer once you move on), a meta description, a canonical address, Open Graph / Twitter tags with `images/og.jpg`, WebApplication structured data and a `<noscript>` summary with links. Each explorer has a hand-written page, `explore/<slug>.html` (its own title, description, picture, explanation, things to try, links into the app and to the others), listed in `sitemap.xml`; the explorer's card links to it (`PAGE` in `tour.js`). Keep those pages true when an explorer changes, and add a page (and a sitemap line) for a new explorer. The pictures were taken at 1200×630 with the panel and text hidden.
- Slow graphics (`js/shell/perf.js`, loaded first by `main.js`): at start it asks for a WebGL 2 context with `failIfMajorPerformanceCaveat` and reads the renderer's name (SwiftShader, llvmpipe, Microsoft Basic Render Driver… mean no graphics card). Software drawing shows a notice once a device (`mathexplorer.slowNotice`) on turning hardware acceleration on; `lowGraphics()` (software, no WebGL 2, or `deviceMemory` ≤ 2) starts Fractals at the Smooth quality unless the viewer chose one. A lost drawing surface on any canvas in the page (`webglcontextlost`, listened for on the way down since it doesn't bubble) shows "The graphics card stopped drawing" with Reload this view (the address holds the view). Analytics: `graphics` (`kind`: gpu / software / none) once a visit and `graphics_lost`. Test browsers draw in software, so the notice is off under `navigator.webdriver` unless the address has `?perfTest` (`?perfTest=software` / `?perfTest=lost` force each case).
- Analytics (`js/shell/analytics.js`): Google Analytics 4 (`G-LK5Z3FJD40`), loaded only on mathexplorer.thedigitalspace.net, with Consent Mode: denied (cookie-free pings) until the consent bar's Allow (`mathexplorer.consent`). Page views carry only the explorer's name, never the view code (it can hold a hand-drawn shape). Events: toolbar (every button on the picture and in its menus: `button`, `explorer`), explorer_open (`explorer` and `via`: `home` when the plain address, or one naming no explorer, opened the default; `link` for an address naming an explorer; `menu` for a move inside the app, back / forward included; set in `main.js`'s `route(via)`, so Fractals' opens as the landing page can be filtered out), shape_view (`explorer` and `shape`: the Shapes group's name, Growing Patterns' title, once it has stayed about 3 s), the tour's steps and the cards, and, from one capturing click listener (no explorer code), visualizer, fullscreen, snapshot, record_video, share_link, print_3d and the music sources, plus js_error (message only, five a page). `?analyticsTest` shows the bar locally and logs events to `window.__trackLog` without sending anything.

## GitHub

## Music (js/shell/audio/)

One player serves the whole app. Music keeps playing across explorer switches and every explorer reacts to it. Its panel group (`#g-sound` in `index.html`) is moved by `main.js` into the active explorer's panel, right after that explorer's `#g-style` group. Every panel keeps the same group order: Shapes, Controls, (Rotation & motion, or Motion), View & detail, Colour & style, Music & sound, Save, share & record, Numbers/Structure, Learn, 3D print, Keyboard shortcuts. Explorers never touch the audio graph.

What goes where (checked across all twelve explorers; keep to it when adding a control):
- **Shapes**: what you're looking at: the choice, and the numbers that define it (a surface's twists, a torus knot's p and q, an attractor's rule numbers, p / q and Wythoff's kind, Lenia's growth rule and reaction–diffusion's feed and kill, a labyrinth's wall and maze settings, the plate's shape and pattern, the epicycles' drawing, Complex's steps, c and zeros/poles). Per-mode sections are hidden with their mode (Labyrinths marks them `data-for="<kind>"`).
- **Controls**: things you do and play with: start, step, ride, walk, fly, solve, paint, presets, simulation speed.
- **Rotation & motion / Motion**: everything that moves by itself: Keep turning and its speed, glide, the camera motions and Slowly change.
- **View & detail**: how it's drawn: detail, draw as, slice, model, cells shown, trails, mist, Show it on (plane / sphere).
- A control that does nothing in the current mode is hidden, not left inert (Background in Waves' ripples and on Complex's plane; Tilings' Controls group outside the random patterns; Strange Attractors' Path length only for a path, Particles and Trails only for a swarm, no View group for the butterfly effect, and for maps no turning, camera, Colour by or Finish; Labyrinths' Detail only for the surfaces, Colour by only for surfaces and foams, and in the maze, which is always first person, no turning, camera or Finish). Motion sections are hidden by id (`#mvTurnSec`, `#mvCamSec`), never by position: the Visualizer's section sits first. Checked by changing each control alone from a fresh page with motion paused and comparing screenshots; walk-, ride- and fly-only settings stay visible so they can be set beforehand.
- Each panel's Keyboard shortcuts list is the explorer's own rows plus the shared ones; a shared row whose key the explorer redefines (`+ / −` in Knots, Labyrinths, Waves, Growing Patterns) is left out, so no key is listed twice. Reset view lives on the stage (and R), not in panels; Tilings' "Back to the middle" is its glide's own reset. Complex always takes its angle colours from the palette (default `wheel`, the classic colour wheel): a palette that ends where it starts (`loops()`) runs once round, any other out and back, so there's no seam; links from before (no `ac=p`) open on the wheel.

- `frames.js` turns raw samples into spectral frames at a fixed hop (512 samples), each stamped with its audio time. It runs in an AudioWorklet (`frames-worklet.js`). AudioWorklet needs a secure context, so on plain-http hosts `engine.js` falls back to a ScriptProcessor. Keep both paths working.
- `analysis.js` does all beat work per frame on the audio clock, never per screen frame, so results are identical at any frame rate:
  - auto-levelled bands
  - onset detection with an adaptive threshold
  - tempo from a smoothed tempogram: autocorrelation of the bass and the mid/high onset curves, each weighted per song by how clearly it pulses, then folded into 85–170 BPM
  - confidence as how consistently recent windows agree with the tempo (octaves and 2:3 count as agreeing), not as absolute correlation strength, because that varies hugely between songs
  - beat phase by folding onsets over the beat
  - bar start from where the bass falls
  - energy against the song's long-run loudness
  `update()` only places the beat clock at the moment being heard (output latency plus one frame).
- `engine.js` handles playback: a file, the microphone, or another tab's sound. "Listen to a tab" uses `getDisplayMedia` with audio. It needs desktop Chrome or Edge on a secure page; the captured audio isn't sent to the speakers; a `CaptureController` asks Chrome not to jump to the shared tab; and the share ending in the browser bar stops it. To test it headlessly, use a second page plus `--auto-select-tab-capture-source-by-title=<title>`, without puppeteer's default `--mute-audio` and without `--use-fake-ui-for-media-stream`, which substitutes a fake silent device. Also handled:  pause/resume bookkeeping (`analysis.pause/resume`, which also skip the silence-to-music windows that would read as a false hit), and `recordTracks()` for video recording.
- `react.js` is the only thing explorers should import. It holds the panel settings (saved in localStorage) and helpers that already respect them:
  - `flash()` / `pulse()` (0..1) are the beat effect. Only one is non-zero, depending on the panel's "On each beat" choice: Flash brightens (the `u_flash` shader uniform in fractals, light intensity in polytopes); Pulse moves the shape.
  - `voice()` is a slow sway in -1..1 around the vocals' recent level. Use it for at most one gentle parameter per scene.
  - `shimmer()` is treble (0..1); `energyMul()` is a speed multiplier; `colourStep(dt)` advances the palette.
  - Keep the mapping sparse: every extra parameter the music moves at once makes the picture read as chaos, not rhythm. That was the "jumpy" complaint behind this design.
  - `new Phase().step(value, dt, period, cycleBeats(n), freeRate)` is for periodic motions: their cycles land on bar lines when the tempo is locked. It never jumps: its speed eases over about 1.5 s when the lock or tempo changes, and it catches up with the bar at most ±25% faster or slower. An earlier version snapped into place, which made Breathe lurch.
  - Choose `n` by how much the motion changes the picture. Turning and twisting can cycle every "Slow motions take" bars (`n=1`), but Breathe reshapes the whole object and uses `n=4`; at bar speed it "hit too hard".
  - `new Groove().delta(dt, perSecond, perBeat, steps)` is for advancing motions: they surge on each beat. Pass `steps=true` when exactly one step per beat matters.
  - `BeatGate` reports beat crossings.
  - Each motion owns its own `Phase`/`Groove` instance (see the `clk` objects in each explorer's `loop.js`).
- Each explorer's `index.js` exports `soundHelp`, the text shown under the switches saying what reacts in that explorer. Keep it true when you change what reacts.
- In the ten newer explorers every mode answers both beat styles (Flash and Pulse), because choosing one turns the other off, and a mode without it simply ignores the beat. Checked by playing music with motion paused and correlating the picture with `flash()` / `pulse()`, on the test track and on real songs.
  - Flash: shaders use `col*(1.0+0.35*u_flash)+0.05*u_flash`, as Fractals does (the added glow is what makes dark pictures visibly flash); canvas-drawn modes brighten by the same amounts and lay a 5% white veil over the frame. In 3D, materials the lights don't reach (lines, Neon, Bubble, the foam's edges) are registered with `S.addFlash` and brightened directly by `S.setFlash`.
  - Pulse is applied only as the picture is drawn, so it never reaches share links or fights the Motion zoom: `view2d`'s `beat` (`v.eff()` is the drawn scale, and `toScreen` follows it, so markers stay put), Life's display zoom, a canvas transform (Tilings' patterns, Waves' drawn modes), `S.pivot.scale` in Labyrinths (its fit scale is set by each build), and exposure for Strange Attractors' maps (zooming would wipe the picture they build up).
  - Beat surges: `Groove` with perBeat = half of perSecond, as in Fractals and Polytopes, so turning runs at the same speed with or without music at 120 BPM.
- **Intensity** (Calm / Lively / Wild, `settings.intensity`, in the shared panel, default Calm): the newer explorers import `flashFx`, `pulseFx` and `voiceFx` *as* `flash`, `pulse` and `voice`, so their code reads the same; at Calm they equal the plain helpers. Lively ×1.7 and Wild ×2.6 (`boost()`), scaled by the passage's energy and by `lift()` just after a drop, plus a little of the bass level itself between hits. Polytopes imports the plain helpers, so Intensity doesn't touch it. Fractals uses the boosted ones too, and its 3D shapes dance while music plays (`dance()` in `modes/fractal3d.js`): the camera nods toward its target on each beat (`beatLevel`), the shape leans side to side across two beats and twists back and forth across four, locked to `beatPos()` when the tempo is locked, and the bass flexes the twist further (`bassLevel`), all scaled by `boost()` and the passage's energy, eased frame to frame, and applied only to what's sent to the shader (the camera position, `u_rot3`, `u_twist`), so dives aim and prints build from the true view. Wild is the full dance and Calm a gentle sway (factors 0.14 / 0.45 / 1, not straight with `boost()`, which made even Calm look wild). Measured with a real song: lean about 3° / 11° / 22° and nod about 2% / 8% / 17% at Calm / Lively / Wild. In 3D the hint says how to both turn and move: dragging does one (the Dragging setting, `st.d3.dragMode`: Move by default, or Turn around), Shift-drag or right-drag the other; on a touch screen one finger looks around and two fingers move (swapped when Dragging is Turn around), and pinch still moves closer. Share links store `drag=turn` only when it isn't the default.
- `analysis.js` also tells hits apart (`kick` when the bass carries most of the onset, `snare` when the mids do, with counts) and finds the song's sections: `section` / `sectionKind` 'drop' when the energy rises 0.2 above its ten-second average (and is above 0.55), 'calm' when it falls 0.2 below; not in the first 12 s, at least 16 s apart; `lift` fades over 2 s after a drop. `react.js` turns these into `kick()`, `snare()`, `lift()`, `HitGate` and `Director` (a 'phrase' event every eight bars when the tempo is locked, every 20 s otherwise, kept 10 s clear of other events; a 'calm' within 8 s of another event is dropped).
- **The Visualizer** (`js/common/visualizer.js`, `makeVisualizer(MO, cfg)` in each newer explorer, a button at the top of its motion group and `#vizStageBtn` in the picture's ♫ menu, which the explorer on screen claims and `main.js` hides on every switch): saves the motion settings, applies the explorer's preset, ticks Keep turning, goes full screen and raises Intensity to Lively if it was Calm. On each Director event: a phrase changes one thing (shape, palette, swept slider, colour mode, how it turns, or the explorer's extras, never the same twice running), a drop runs the explorer's big change (ride the knot, fly the labyrinth, a swarm, glide, a fresh start…; undone at the next event), a calm passage drifts the palette. Kicks and snares call the explorer's own small reactions (seeds in Lenia and reaction–diffusion, splashes in the tank). Stopping, or switching explorer (caught on `hashchange` while the panel is still attached), puts everything back; the motion module looks its controls up inside its own group so loading settings works while the panel is detached. Checked with the songs in the user's Downloads (not in the repo): changes land every 12–20 s, on choruses and drops, at 60 fps.
- To check analysis changes, run a track through `FrameMaker` and `Analysis` directly: decode it, push 128-sample blocks, call `update()` at a simulated frame rate. Then compare tempo, lock percentage, and how close strong hits land to whole beats (`Analysis.hits = []` records them). Check several songs of different styles, because a tweak that helps one kind of beat can break another. `engine.analysisForDebug()` gives the live instance. There's no test suite for this in the repo.

## Shared modules (js/common/)

The ten newer explorers are built from these; Fractals and Polytopes use the first three (the old paths re-export them).

- `colours.js`: the colour controls under every explorer's swatches (called by `buildSwatches`, and by Fractals' and Polytopes' own swatch code): Hue, Saturation and Light (`ADJ` in `palettes.js`, applied by `adjust()` inside `rampOf`, so every colouring, cycle and reverse uses the adjusted colours; hue turns in YIQ, keeping brightness) and Your palette (`PALETTES.mine`, 2–6 colours, remembered in localStorage `mathexplorer.mine`; Make your own starts it from the palette on screen). One set of values for the whole app; a change re-clicks the chosen swatch so the explorer recolours through its own code, and an explorer coming back on screen recolours if they changed (`colourSync`). Share links carry them through the shell, not the explorers: `route.js` appends `setCodeExtra()`'s part (`hue`, `sat`, `lit`, and `mine` while it's chosen) to every view code, and `main.js` reads them with `colourFromCode` before the explorer sees the code; a code without them means plain colours. Explorers must not use those keys. 40 palettes, including wide ones (spectrum, turbo, spectral, cubehelix, twilight, carnival, opposite-colour pairs, bold); `palTitle` names them.
- `palettes.js`: `PALETTES`, `rampOf`, `sampleRamp`, `sampleMirror`, `rampUniform`, and `PAL_GLSL`. The GLSL `pal(t)` is **mirrored** so it cycles seamlessly: t from 0 to 0.5 runs the palette start to end, 0.5 to 1 runs it back. For an amount from 0 to 1, look up `pal(v*0.5 + u_cycle)`; plain `pal(v)` makes 0 and 1 the same colour (that bug made Lenia's full cells and the waves' crests look empty). Angles and repeating bands can use it unhalved.
- `formula.js`: the custom-formula parser with `toGLSL`, `toJS`, `usesVar` and `FORMULA_GLSL` (the complex helper functions). Fractals and Complex Functions share it.
- `three-stage.js`: `bubbleMaterial`, `makeFinishes()` and `makeStage3D()` (renderer, pivot and fit groups, drag inertia, drive keys).
- `gl.js`: `makeGL(canvas)` for full-screen shader explorers: `prog(fs)` (cached, `.p` and `.u(name)`), `draw(fb, w, h)` with the program in use, `tex`, `fbo`, `pair` (ping-pong) and `fit`. `tex` is half-float by default; pass `full: true` for 32-bit floats when a simulation's steps are tiny (Gray–Scott recipes such as Dividing cells died at half precision), and `float: false` for a texture you read back with `readPixels` as bytes (reading half floats as bytes fails silently). - `visualizer.js`: the Visualizer button, its director and its Learn topic ("Moving with music"), built on a motion group (see "Music" above).
- `motion.js`: the motion groups and the recorder for the ten newer explorers, each inserted from JS right after `#g-ctl`.
  - `makeMotion3D(S, opts)` ("Rotation & motion"): Keep turning (the explorer's own row and speed slider are moved in), round or rock, tumble, a zoom slider, In & out, Drift. Explorers call `MO.step(dt, { go, away, spin })` instead of turning the shape themselves: `away` (walking, riding, flying) takes the camera offsets off, and they ease back in afterwards. The camera offsets are kept as what was added last frame, so drags, the wheel and W A S D still work on top; `S.reset` is wrapped to forget them, and share links store `MO.baseZ()`.

  - "Slowly change the shape" (in both) sweeps any range input in Shapes, Controls or View & detail (less `skip`) round where it was, by dispatching `input` events, so each slider's own handler does the work. `every` throttles heavy rebuilds (Labyrinths 120 ms); `far` sets a narrower default (Lenia 6%: wider kills it). A trusted `input` on the swept slider moves the centre of the sweep. Strange Attractors treats an untrusted parameter change as a live morph: the flow keeps going under the new rule rather than restarting.
  - Share keys all start with `mv`. `addRecorder({ stage, name, bg })` adds Record video to the Save & share group: it draws every visible canvas in the stage, where it sits on screen, into a recording canvas at 30 fps, plus `recordTracks()` for the music. All canvases use `preserveDrawingBuffer`, so the recorder can read them between frames. Polytopes uses it too (its insets are recorded with it); Fractals keeps its own recorder (`fractal/io/recorder.js`).
- `view2d.js`: pan / zoom / pinch / drive keys for 2D views, and a turn (`rot`: `toWorld`, `toScreen` and `pan` all follow it; the shader turns its screen offset by it). `glide`, `zoomBy` and `rotate` serve the Motion group. `kit.js`: panel helpers, `standardKeys`, `buildKeys`, `makeShare` (wires the Share group). `save.js`, `stl.js` (`stlFromTriangles`, `tubeTriangles`, `heightfieldTriangles`).

Recheck if you edit a formula. The up vector is carried along continuously, and comparing it with the formula's normal tells which side you're on. At a seam, `reseat` tries the whole and half period shifts and the reflections (about the ends, the middle and the quarter points; the Klein bottle's seam (π, v) ~ (0, π − v) needs the quarter points), then keeps the candidate whose point is closest. Checked: the Möbius band (one twist), Klein bottles and Boy's surface flip sides; the torus, sphere and a two-twist band don't. On open strips T drifts toward the middle of v, or the walker leaves the band. Crossing an edge of the (u, v) domain tries the seam match only where that edge is glued (`wrapU` / `wrapV` / `closed`) or collapses to a point (a pole, found by comparing two points along it); any other edge is open and turns the walker back. Each bubble is cut from a big box (or a tube's prism, or a slab between plates) one bisecting plane at a time, nearest neighbours first, stopping once no farther plane can reach; corners exactly on a plane go onto the new face, so the very symmetric crystals lose no faces. Each face records the neighbour (point and image offset) it faces, so the piece on screen (copies of the repeat cut to a ball, cube, length of tube or disc) draws every shared film once. Checked: the cells fill the box exactly; Kelvin's wall score (surface ÷ volume^⅔) is 5.315 and Weaire–Phelan's 5.295 (flat films); C15 has 16 twelve- and 8 sixteen-faced bubbles, C14 8 and 4, Z 3, 2 and 2 (12, 14, 15), σ 10, 16 and 4 (12, 14, 15), and every Frank–Kasper face is a pentagon or hexagon; random points give about 15.5 faces a bubble. ## Module conventions inside an explorer

These modules came from splitting large single-file apps, and they keep that code's dense style (many statements per line, short names). Match it when editing.

- **Load order is the import order in `index.js`, and it matters.** Modules are layered so that every import points to a module listed earlier in `index.js` (for example util → state → geometry/maths → render → modes → ui → io → input → loop). Top-level code runs at import time (building shape tables, wiring DOM listeners), so a module must not import from a later one. If a lower module needs to call something higher up, move the function down to the lowest module it fits in, rather than adding an upward import.
- ES imports are read-only. A top-level variable that several modules reassign lives on the `shared` object in `<explorer>/shared.js` (`shared.dirty = true`). A variable that only its own module reassigns can be a plain exported `let`.
- `st` in `state.js` is the explorer's single settings object. Changing a setting usually touches the panel markup (`panel.html`), its wiring (`ui/controls.js` or `ui/learn.js`), the code that reads it while drawing, and the view-code encoder/decoder in `io/share.js`. Keep old view codes loading.
- The "Learn" sections are user-facing explanations written in plain English with no jargon; comments follow the same style.

### Fractal explorer specifics
- Frame pacing lives in `loop.js` (`pace`, `adjustPace`). When a moving scene can't hold the screen's rate, it draws on every other refresh (an even 30 fps), checking for headroom every 8 s. Render quality `st.q` changes only in small steps, after real measurements: uneven frames and quality swings looked far worse than a steady lower rate. `pace.simulate` lets tests imitate a slow graphics card, because headless Chrome doesn't wait for the GPU. The viewer's "While moving" choice (`st.motionQ`: smooth / balanced / sharp, saved in localStorage, not in share codes) sets where `st.q` starts, its ceiling while moving and its floor, through `qLimits()` in `state.js`. Dives get a slightly higher floor.
- While recording at 720p/1080p, `shared.recCapH` caps the render size to the video's height.
- Dive steering (`startGrid`/`finishGrid` in `view.js`) scans a coarse grid and pulls toward the busiest edge. While the middle of the view is in the black (`st.steerCentreIn`), it favours a random direction chosen per dive (`st.steerPref`) and the zoom eases off. Without that, a mirror-symmetric view such as the whole Mandelbrot set pulls equally both ways and dives straight into the black. The same setting (`st.steer`, one box in each mode plus T, off by default because it felt too aggressive) steers 3D dives: `steer3Step` in `modes/fractal3d.js` casts a 7×7 fan of CPU rays round the view, within about 3 ms a frame. It scores how sharply depth jumps between neighbouring rays and turns in place toward the best spot when it clearly beats straight ahead. Steering with the keys (`st.keyDriveT`) or dragging puts it on hold.
- `d3Bound()` is the sphere the 3D ray-marcher starts in, and the camera distance is fitted from it. A shape that reaches past it is drawn sliced off as a ball. The Mandelbulb (`bulbBound`, by power, including negative powers) and the Mandelbox (`boxBound`, by scale, including positive scales) size it from measurements: rays marched inward with the same distance formulas. Remeasure if you change a formula or a range. Power −2…2 and box scale −1.1…1.5 are dead zones that the sliders snap out of (`snapGap`).
- The Twist slider's range depends on the shape (`twRange` in `ui/controls.js`): −180…180 for most shapes (negative is the mirror-image spiral), but the kaleidoscopes turn their folded wedge and are empty outside about −20…70° (3D) and 0…50° (4D).
- `fractals/types.js` (`TYPES`) defines the families. `render/webgl.js` holds the GLSL shaders as strings, plus context setup.
- The 3D shader is built **per shape, on demand**. `FS3` is only the source text. `fs3For(i, glass)` cuts out the shared header, that shape's `deX` function (with the constants and helpers just above it), a one-line `mapRaw`, and the shared drawing code. The see-through block sits under `#ifdef GLASS`.
  - `prog3()` in `modes/fractal3d.js` builds the program for the current shape and see-through setting, then drops the others with `main.drop`. Leaving 3D, or the explorer, calls `drop3()`.
  - One program with all 20 shapes took Windows' Direct3D shader compiler minutes, or failed. Per shape, it's 0.3–2.5 s.
  - When adding a shape: put helpers used by more than one shape in the header (as with `rotYv`, `mDE2`), and add the function name to `DE3` in SH3 order.
  - Long fixed loops compile slowly there because they get unrolled. Starting a loop at `min(u_it3,0)` prevents that.
- Deep zoom uses three precision tiers: doubles, double-double (`math/double-double.js`, about 32 digits) and 416-bit BigInt fixed point (`math/big-fixed.js`, about 125 digits). It uses perturbation: a reference orbit is computed on the CPU (in a Blob-URL worker for Extreme precision), uploaded as a texture, and sped up with BLA (`render/bla.js`).
- Custom formulas (`formula/formula.js`) are compiled twice, by `toGLSL` and by `toJS`. Both must give the same results.
- The Apollonian packing (`soddy`, `deSoddy`) flips points through five partner spheres. Alongside, it carries the chain of flips as a 5×5 matrix acting on each sphere's five numbers (co-curvature, curvature, curvature × centre), so every nearby ball's real centre and radius are exact. Two earlier attempts left visible seams: limiting detail by number of flips (balls got half drawn), and shrinking the balls to keep them apart (a flip doesn't map a shrunk ball onto itself). So detail is a minimum ball size (`soddyMin`), applied to whole balls. Keep the shader version lean: the matrix rows are named variables, and the partner-sphere numbers are picked with `if`s, not arrays indexed at run time. After each flip, only the replaced ball and the middle ball are re-measured, since balls the flip crosses at right angles stay put. A version that did neither took 2.8 s a frame on an Intel card, and Windows reset the GPU. Measure frame cost with a `readPixels` after `render3D`; `gl.finish()` does not wait in Chrome. "Apollonian foam" (`apo`) is the older fold-based slab.
- Cast shadows are an option (`st.d3.shadows`, off by default, kept in share codes). When on, the shadow ray is compiled in (`#define SHADOWS`, a separate per-shape program) and cast in every frame. They used to be drawn only in the still, full-quality redraw (`u_hq`), which made the still picture 8–24% darker than the moving one. Keep the moving and still pictures lit the same way.
- See-through bubbles (`st.d3.glass`, `u_glass`) marches on |distance|, so it can also find its way out of a solid. Each surface crossed is shaded as a soap film and blended front to back, up to six crossings. The shared colour lookup is `baseCol()`.
- The hyperbolic honeycomb (`hyp`, `deHyp`; kinds in `HYP`, mirrors from `hypMirrors`) folds with three planes through the centre plus one face sphere orthogonal to the ball. Detail is a cell-size cut-off (`dsMax`), not a fold count: past it, cells aren't opened up, because drawing them all turned the rim into noise. Walls are drawn only for the middle cell and its neighbours. Its 2D cousin in `ui/insets.js` is the matching disc tiling {p,r}, drawn per pixel with the same folding.
- 3D print (`io/print3d.js`) samples `printDE()` from `modes/fractal3d.js` on a grid. It skips 4×4×4 blocks that are clearly outside, thickens the shape (everything within half the minimum wall counts as inside), keeps the biggest connected piece and wraps it with surface nets. The STL is written in millimetres with the explorer's y axis up. The build spans many frames, so `freeze3(true)` makes the distance functions read a frozen copy of `st.d3` (via `D3()`), and a Breathe can't change the shape halfway through. Camera helpers (`cam3`, `d3Mag`) keep reading `st.d3`. The Mandelbox's distance never goes negative, so "inside" is always "within a little over half a grid step", never "below 0". A Downloads-in-Claude save goes in a zip (`js/shell/zip.js`, shared with the polytope export).
- Swapping with the Julia panel (`juliaSwap` / `juliaAt` / `juliaBack` in `ui/controls.js`): the picture's Julia button, a click on the panel at top right (`#in2`; a double tap on touch screens, and the shell's tap gestures leave `#insets` alone) and J all put what the panel shows into the main view (the Julia set at the middle, or at the pointer while it's over the picture) and keep a copy of the view (`shared.juliaBack`); the panel then shows where c sits on the map, and swapping again restores the view exactly. Explore only, for fractals with Julia sets. On the Julia link screen the same button, J, and a double tap or double click on the Julia side open that Julia set full screen (`#linkOpen`); the canvas is `data-own-taps` there, so the shell's taps leave it alone.
- Two fingers twisting turn the 2D picture (explore) round the point between them, after a 10° dead zone so pinching doesn't wobble it (`twistAt` in `input/pointers.js`); the Rotate slider and share links follow `st.rotDeg`.
- Colour-only changes (palette, reverse, density, colour mode, background) call `recolour()`, not just `touch()`. The loop then redraws straight at full quality. Otherwise the picture flashed soft for a moment at the moving resolution before sharpening.
- `window.__fx` exposes internals for console debugging.

### Polytope explorer specifics
- `geometry/` builds every shape as vertices on the unit 3-sphere plus edges, registered in `SHAPES` (`geometry/polytopes.js`). Several sections add more shapes at load time (stars, compounds, round, higher-dim, prisms, wythoff), many built lazily and cached.
- The Apollonian packing (`apack`, end of `geometry/round.js`) is made of caps on the 3-sphere, each kept as five numbers `(centre, cos r)/sin r`; two caps touch when their form is −1. A new ball is "sum of the other four − this one". The 3D filling rule can reach the same ball twice, so duplicates are merged. In Balls view, `render/packing.js` draws each cap as an exact sphere under true stereographic projection. The cap holding the pole becomes the glass container. `updateGeometry` hands the balls to the 3D print as a balls-only frame, and the print enlarges each ball 4% so touching balls fuse. The packing always uses stereographic projection and has no Slice. A ball bigger than `BIG` (it is swelling towards becoming the container) is drawn as a faint glass shell, not solid, so it cannot fill the view.
- "Draw as" (`st.drawAs`, Explore only):
  - **Touching balls:** `render/packing.js` puts a ball at every corner with radius half the closest pair's angle (`capsFor`, cached in `sh._kiss`), drawn exactly like the packing.
  - **Bubble foam:** `render/foam.js` pushes each face onto the 3-sphere, where it lies on a great sphere, so it projects to an exact sphere. Normals come from that sphere's centre. The subdivided points are built once per shape; each frame only turns and projects them with plain arithmetic (allocating per point cost 40+ ms a frame), then re-sorts whole faces back to front.
  - Both views force stereographic projection (`roundView`).
- Stereographic projection of ordinary corners and edges (`project` in `math/rotate4d.js`) eases W above 0.84 (`softW`, within about 33° of the pole) so nothing shoots off screen; the packing, touching balls and bubble foam use the exact 1/(1 − W). The Learn text ("What you're seeing") says so; keep it true if either changes.
- The "Bubble" finish is `bubbleMaterial()` in `render/scene.js`: a thin-film ShaderMaterial that works on instanced balls (instance colour) and on vertex-coloured meshes. Transparent balls are sorted back to front each frame.
- Flying (`input/fly.js`, G): the camera leaves its spot on the z axis and moves freely. Normally it never rotates, and the shape group (`pivot`) turns instead.
  - Speed eases down near the middle.
  - Once past the middle and heading out without steering (beyond 0.3 × the shape's measured reach), it curves back toward a random point inside the shape; waiting until it had left the shape gave seconds of black screen.
  - Stopping, or Reset view, restores the axis camera.
  - Not flying, the arrows turn `pivot` like a drag and W A S D slide the camera sideways.
- The modes (`modes/build.js`, `modes/unfold.js`, `modes/ping.js`, plus slice and explore) decide what to draw. `render/scene.js` owns the three.js scene, and `loop.js` holds the per-frame update. The inset canvases are drawn by `panels/`.
